# Последовательный перевод книги

Координируй перевод по одной главе и фиксируй результат только после полной приёмки. Основной контекст управляет файлами и ролями, но не переводит и не редактирует художественный текст.

## Вызов и значения по умолчанию

Обычный вызов из чата:

`/book-translator [ПАПКА] [формат: pages|docx|как-в-оригинале] [продолжить|начать-заново]`

Равнозначна естественная русская команда о переводе книги. Параметры текущего сообщения важнее `config.ini`.

- Папка по умолчанию — текущая папка.
- Формат по умолчанию — значение `config.ini`, затем `как в оригинале`.
- Режим по умолчанию — `продолжить` с последней успешной контрольной точки.

## Предварительная проверка

До первого агента:

1. Разреши абсолютный путь проекта и инициализируй только отсутствующие служебные файлы.
2. Покажи фактические путь и версию Python 3.10 или новее; проверь `python-docx`. Если пакет отсутствует, покажи точную команду установки, запроси разрешение и не устанавливай его скрыто.
3. Проверь операционную систему, входные и выходной форматы. Для `.pages` проверь macOS и Pages; экспорт или импорт выполняй только после явного разрешения. На Windows остановись с инструкцией использовать DOCX либо Mac с Pages.
4. Проверь чтение исходников, запись в служебные каталоги, целостность DOCX, поддерживаемое оформление, однозначный порядок глав, манифест и конфликты выходных имён.
5. Проверь наличие четырёх custom agents. Если они недоступны, остановись, покажи русскую команду предпросмотра `scripts/install-agents.py --plan` и инструкцию подтверждаемой установки; не подменяй их общим агентом.
6. В режиме `начать-заново` сначала покажи предпросмотр `output/`, `state/`, `progress.json` и рабочих контрольных точек. Получи подтверждение пользователя и вызови `restart_project` только после проверенной резервной копии. Исходники не затрагивай.
7. Если обработанный исходник изменён, остановись и предложи выбор: сохранить прежний результат либо заново перевести изменённую и все последующие главы. Не выбирай за пользователя.

## Неподвижные правила

- Никогда не запускай главы, части главы или ролевых агентов параллельно и не готовь следующую главу заранее.
- Иди строго по `work/manifest.json`; следующую главу начинай только после успешной фиксации предыдущей.
- Не выполняй художественный перевод или редактуру в основном контексте.
- Для каждого ролевого этапа запускай новый экземпляр named custom agent с чистым контекстом. Не передавай историю родительской беседы, рассуждения или текстовые ответы прежних агентов.
- Стартовое задание содержит только роль, абсолютные пути необходимых входов и ровно один абсолютный output. Результаты этапов передаются путями к файлам.
- Дождись агента, проверь существование и пригодность ожидаемого артефакта и лишь затем вызывай `advance_stage`.
- Любая механическая ошибка немедленно блокирует главу. Исходники, последняя принятая память и опубликованные главы остаются неизменными.

## Порядок одной главы

1. При необходимости экспортируй Pages во временный DOCX внутри `work/`, затем `extract_docx` и этап `извлечение`.
2. Запусти новый `book_translator_translator`, проверь его единый JSON и зафиксируй `перевод`.
3. Выполни `validate_translation`; сохрани результат и зафиксируй `полнота_1`.
4. Запусти новый `book_translator_verifier`; сохрани `report-1.json` и зафиксируй `проверка_1`.
5. Запусти новый `book_translator_editor` только с актуальным отчётом; проверь `edited-1.json` и зафиксируй `редактура_1`.
6. Снова выполни `validate_translation`; зафиксируй `полнота_2`.
7. Запусти второй новый `book_translator_verifier` без `report-1.json`; сохрани `report-2.json` и зафиксируй `проверка_2`.
8. Если статус `report-2.json` не `пройдено`, через `request_second_edit` запусти ровно один дополнительный новый `book_translator_editor`, проверь его результат через `validate_translation`, а затем запусти третий новый `book_translator_verifier`. При критической ошибке этот дополнительный цикл обязателен. Третья редактура запрещена. При оставшейся критической ошибке или требовании редактуры остановись, сохрани отчёт в `work/` и не публикуй главу.
9. После статуса `пройдено` обозначь единственную актуальную версию как `accepted.json`, собери временный результат через `rebuild_docx` и проверь его через `inspect_docx`. Для результата Pages после явного разрешения импортируй проверенный DOCX и проверь созданный файл; промежуточный DOCX не публикуй. Только после проверки зафиксируй этап `сборка`.
10. Только один раз после окончательно принятой и собранной главы запусти новый `book_translator_state_updater`. Не после части, черновика или неуспешной проверки. Он готовит полную память в `transaction/new-state/`, не изменяя действующий state. Проверь все файлы следующей памяти и зафиксируй этап `память`.
11. Вызови `prepare_transaction`, проверь маркер готовности и `commit_transaction`. Только после успешной фиксации и проверки согласованности переходи к следующей главе.

## Длинная глава

Начальный верхний предел части — 60000 символов. Если глава не помещается, вызови `split_blocks` и дели только между блоками; запиши порядок частей в `chunks-manifest.json`.

Запусти один экземпляр translator на всю главу. Этот один экземпляр translator читает части главы последовательно, удерживает краткое состояние сцены, незавершённые связи и небольшой контекстный хвост оригинала и перевода. Хвост используй только для понимания: не записывай повторно. Не запускай отдельного translator для частей и не создавай новых абзацев на их границах.

## Самопроверка координатора

- В каждый момент активна одна глава и не более одного ролевого агента.
- На все части главы был один translator.
- Каждый verifier и editor был новым экземпляром; verifier 2 и verifier 3 не видели прежних отчётов.
- Редакторских циклов не больше двух.
- `state-updater` запущен один раз после принятия и сборки.
- Следующая глава не начата до транзакционной фиксации текущей.

## Ошибочные сокращения

Не считай экономией времени параллельную подготовку следующей главы, память после каждой части, возврат замечаний verifier тому же translator или редактуру «до чистого результата». Это нарушает изоляцию и контрольную точку: замечания исправляет новый editor, память меняется после принятия главы, а после двух редактур процесс останавливается.
