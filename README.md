# Переводчик художественных книг для Codex

Локальный плагин переводит английские главы на русский строго по одной: извлекает блоки, проверяет полноту и смысл, собирает результат и только затем фиксирует память проекта.

## Возможности

- Обрабатывает английские `.docx` в русские `.docx` с сохранением поддерживаемого оформления.
- На Mac может обработать `.pages` через установленное приложение Pages, но только после явного разрешения пользователя.
- Сохраняет манифест глав, контрольные суммы, контрольные точки и позволяет продолжить после прерывания.
- Для каждого ролевого этапа использует отдельный custom agent с чистым контекстом.

## Требования

- Локальный Codex и Python 3.10 или новее.
- Установленный пакет `python-docx` версии 1.2 или новее, но ниже 2.0. Плагин сам его не устанавливает: при отсутствии он покажет команду и запросит разрешение.
- Для полного конвейера нужны четыре локально установленных custom agents.
- Pages нужен только для `.pages` на Mac. На Windows используйте DOCX либо перенесите проект на Mac с Pages.

## Локальная установка плагина

Подключите каталог этого плагина как локальный плагин Codex. До запуска просмотрите `hooks/hooks.json` и разрешите hook только если его команда вам подходит: он проверяет согласованность активного перевода при остановке.

Не устанавливайте зависимости и не запускайте Pages скрыто. Плагин сначала сообщает, что именно нужно сделать, и ждёт явного разрешения там, где оно требуется.

## Однократная установка custom agents

Подставьте абсолютные пути. Сначала выполните предпросмотр без записи, затем отдельно подтвердите запись.

### Команды для Windows (PowerShell)

```powershell
& "<путь-к-python>" "<абсолютный-путь-к-плагину>\skills\book-translator\scripts\install-agents.py" --source "<абсолютный-путь-к-плагину>\agents" --target "<абсолютный-каталог-agents-Codex>" --plan
& "<путь-к-python>" "<абсолютный-путь-к-плагину>\skills\book-translator\scripts\install-agents.py" --source "<абсолютный-путь-к-плагину>\agents" --target "<абсолютный-каталог-agents-Codex>" --confirm
```

Оператор `&` обязателен: без него PowerShell не запускает путь к исполняемому файлу в кавычках.

### Команды для POSIX-систем

```sh
"<путь-к-python>" "<абсолютный-путь-к-плагину>/skills/book-translator/scripts/install-agents.py" --source "<абсолютный-путь-к-плагину>/agents" --target "<абсолютный-каталог-agents-Codex>" --plan
"<путь-к-python>" "<абсолютный-путь-к-плагину>/skills/book-translator/scripts/install-agents.py" --source "<абсолютный-путь-к-плагину>/agents" --target "<абсолютный-каталог-agents-Codex>" --confirm
```

Если план сообщает `отличается`, не перезаписывайте файл автоматически. После отдельного подтверждения точного имени добавьте `--overwrite "<точное-имя.toml>"` к команде с `--confirm`.

## Подготовка папки книги

Поместите главы `.docx` в папку `input/` проекта либо прямо в его корень, но не в оба места сразу. Имена определяют естественный порядок: `chapter-2.docx` идёт перед `chapter-10.docx`.

Исходники читаются только для проверки и извлечения: они не изменяются, не перемещаются и не удаляются. Рабочие файлы находятся в `work/`, опубликованные результаты — в `output/`, память проекта — в `state/`.

## Запуск из чата

```text
$book-translator Переведи книгу в текущей папке.
$book-translator Переведи главы из /Книги/Роман, результат — pages.
$book-translator Продолжи перевод, выходной формат — docx.
```

Обычный ChatGPT без локального Codex и четырёх custom agents не выполняет полный конвейер. Главы, части главы и ролевые этапы не запускаются параллельно.

## Выбор DOCX или Pages

DOCX поддерживается на Windows и macOS. Pages поддерживается только на macOS с установленным Pages; экспорт и импорт выполняются лишь после явного разрешения. Для Pages сохраняется проверенный промежуточный DOCX внутри `work/`, а в `output/` публикуется только требуемый формат.

## Продолжение после прерывания

Повторите команду с «Продолжи перевод». Плагин восстанавливает готовую, но не до конца опубликованную транзакцию и продолжает с последней успешной контрольной точки. Перевод уже принятой главы повторно не выполняется.

## Явный перезапуск и резервная копия

Попросите начать заново. Сначала плагин покажет затрагиваемые `output/`, `state/`, `progress.json` и контрольные точки, затем запросит подтверждение. Перед очисткой создаётся и проверяется резервная копия; исходные главы в неё не переносятся и не затрагиваются.

## Что сохраняется в оформлении

Поддерживаются абзацы, заголовки, разрывы сцен, курсив, полужирное начертание и сноски. Таблицы, комментарии, отслеживаемые изменения, связанные текстовые блоки и совместное редактирование первой версией не поддерживаются.

## Ограничения первой версии

Поддерживается только английский → русский. Нет отдельного API, графического интерфейса, MCP-сервера, CAT-интеграции и дополнительных языковых пар.

Реальные приёмки чистого контекста custom agents и `.pages → .pages` на macOS ещё не выполнены в этой среде; подробные честные статусы находятся в `tests/acceptance/`.

## Проверки для разработчиков

Используйте Python, которым будет запускаться плагин.

### Проверки в Windows PowerShell

```powershell
& "<путь-к-python>" -m unittest discover -s tests -p "test_*.py" -v
& "<путь-к-python>" -m json.tool .codex-plugin/plugin.json
& "<путь-к-python>" -m json.tool hooks/hooks.json
```

### Проверки в POSIX

```sh
"<путь-к-python>" -m unittest discover -s tests -p "test_*.py" -v
"<путь-к-python>" -m json.tool .codex-plugin/plugin.json
"<путь-к-python>" -m json.tool hooks/hooks.json
```

Приёмочные протоколы для чистого контекста, Windows DOCX и macOS Pages лежат в `tests/acceptance/`. Они требуют реального запуска и не заменяются проверкой текста инструкций.

## Безопасность исходников

Плагин фиксирует SHA-256 исходных глав в манифесте и останавливается, если уже обработанный источник изменился. Публикация результата, обновление памяти и контрольной точки происходят одной восстанавливаемой транзакцией только после механической и смысловой приёмки.
