# Переводчик художественных книг для Codex

`book-translator-plugin` — русскоязычный плагин для последовательного художественного перевода книг с английского языка на русский. Он принимает отдельные главы или другие части книги в `.rtf` и публикует переводы также в `.rtf`, сохраняя структуру документа, основное форматирование и штатные аннотации.

Плагин рассчитан на продолжительную работу над книгой. Он ведет глоссарий, сведения о персонажах и сюжете, запоминает переводческие решения, проверяет каждую главу несколькими независимыми ролями и позволяет вернуться к уже готовому файлу после изменения пользовательских указаний.

Текущая версия: `0.2.0`.

## Основные возможности

- естественный литературный перевод без англоязычной кальки;
- сохранение индивидуальных голосов рассказчика и персонажей, ритма, повторов и неоднозначности;
- до пяти проверочных раундов по умолчанию с досрочным завершением;
- замечания в виде обычных RTF-аннотаций вместо отдельного пользовательского формата;
- приемка после каждого файла или один раз после всей очереди;
- продолжение работы после прерывания и автоматическое обнаружение новых файлов;
- повторный перевод выбранной главы с актуальным state без изменения последующих результатов;
- точная передача авторского материала любого рейтинга без смягчения и цензуры;
- запрет буквы `ё` в переводе: всегда используется `е`.

## Требования

- ChatGPT App или Codex с поддержкой локальных плагинов и навыков;
- Python 3.10 или новее;
- доступ на чтение и запись в каталог книги.

Внешние Python-пакеты не требуются. Исходные и итоговые документы должны иметь формат RTF.

### Глобальная установка Python 3.10 или новее

Плагину подходит любая версия CPython не ниже 3.10; устанавливать именно ветку 3.10 необязательно. Для новой установки рекомендуется актуальная стабильная версия с [официальной страницы Python](https://www.python.org/downloads/). Под глобальной установкой здесь понимается интерпретатор, доступный из любого терминала пользователя, а не отдельное виртуальное окружение проекта. После установки закройте и заново откройте терминал.

#### Windows

1. Установите официальный [Python Install Manager](https://docs.python.org/3/using/windows.html#python-install-manager) с python.org или из Microsoft Store.
2. В новом PowerShell установите актуальный Python командой `py install default`. Если нужна именно ветка 3.10, используйте `py install 3.10`.
3. При первом запуске согласитесь добавить каталог глобальных команд Python в `PATH`.
4. Проверьте установку:

```powershell
py -3 --version
py -3 -c "import sys; assert sys.version_info >= (3, 10); print(sys.executable)"
```

Python Install Manager устанавливает интерпретаторы для текущего пользователя. Этого достаточно для плагина и для запуска из любого его терминала; общесистемная установка для всех учетных записей не требуется.

#### macOS

1. Скачайте универсальный установщик macOS в формате `.pkg` со [страницы выпусков Python для macOS](https://www.python.org/downloads/macos/).
2. Выполните стандартную установку для всех пользователей, подтвердив ее паролем администратора. Python будет установлен отдельно от компонентов macOS.
3. Проверьте версию и путь в новом Terminal:

```bash
python3 --version
python3 -c 'import sys; assert sys.version_info >= (3, 10); print(sys.executable)'
```

#### Linux

Устанавливайте Python глобально через пакетный менеджер дистрибутива и не заменяйте вручную системный `/usr/bin/python3`:

```bash
# Debian и Ubuntu
sudo apt update
sudo apt install python3

# Fedora и RHEL
sudo dnf install python3

# Arch Linux
sudo pacman -S python
```

Затем выполните:

```bash
python3 -c 'import sys; assert sys.version_info >= (3, 10); print(sys.version)'
```

Если репозиторий дистрибутива предоставляет версию ниже 3.10, обновите дистрибутив либо установите отдельный CPython в `/usr/local` через `make altinstall` по [официальной инструкции для Unix](https://docs.python.org/3.10/using/unix.html#building-python). Команда `make install` не рекомендуется, поскольку может подменить системный `python3`.

> Ветка Python 3.10 получает только исправления безопасности. Python 3.10.11 был последним выпуском этой ветки с классическими установщиками для Windows и macOS; последующие страницы выпусков содержат исходный код. Если нет требования использовать ровно 3.10, выбирайте актуальную поддерживаемую версию Python 3.

## Установка плагина

Репозиторий содержит готовый marketplace. Добавьте его командой:

```text
codex plugin marketplace add vspanov/book-translator-plugin --ref main
```

Проверьте, что источник появился:

```text
codex plugin marketplace list
```

Затем:

1. Перезапустите ChatGPT App или Codex.
2. Откройте каталог плагинов и выберите источник «Плагины BooksRu».
3. Установите `book-translator-plugin`.
4. В новом чате проверьте доступность `$book-translator-init` и `$book-translator`.
5. Просмотрите запрос на подключение stop hook и разрешите его после проверки команды.

Для проверки незавершенных локальных изменений можно клонировать репозиторий и добавить абсолютный путь к его корню как локальный marketplace. Общая схема локальной установки описана в [официальной документации OpenAI о плагинах](https://developers.openai.com/codex/build-plugins).

### Обновление

```text
codex plugin marketplace upgrade booksru-plugins
```

После обновления перезапустите приложение и при необходимости обновите установленный плагин в каталоге. Если marketplace зарегистрирован под другим именем, используйте имя из `codex plugin marketplace list`.

## Быстрый старт

### 1. Создайте рабочий каталог

Вызовите навык инициализации, указав отдельную папку для книги:

```text
$book-translator-init C:\Books\NovelRu
```

Инициализатор подготовит каталоги, настройки, пустой state и проектные ролевые агенты. Существующие пользовательские файлы он не перезаписывает.

### 2. Добавьте оригиналы и пожелания

Положите исходные файлы в `input/`. Удобно использовать нумерацию:

```text
input/
├── 001-prolog.rtf
├── 002-chapter.rtf
└── 003-finale.rtf
```

До начала перевода можно открыть файлы в `state/` и заранее внести утвержденные имена, термины, особенности персонажей, требования к стилю и другие сведения. Пользовательские области state всегда имеют приоритет над автоматическими наблюдениями.

### 3. Запустите перевод

```text
$book-translator C:\Books\NovelRu продолжить
```

Можно обратиться естественно: «переведи новые главы в этой папке» или «продолжи перевод книги». После каждого опубликованного файла плагин показывает кликабельную ссылку на готовый RTF.

## Структура рабочего каталога

```text
NovelRu/
├── input/             # английские оригиналы
├── output/            # опубликованные русские RTF и ревизии
├── state/             # память книги и пользовательские указания
├── work/              # служебные отчеты, резервные копии и транзакции
├── .codex/agents/     # ролевые агенты проекта
├── config.ini         # пользовательские настройки
└── progress.json      # состояние очереди и приемки
```

Обычно пользователь работает только с `input/`, `output/`, `state/` и `config.ini`. Файлы внутри `work/` нужны для безопасного продолжения и восстановления, поэтому удалять или редактировать их вручную не следует.

## Команды и настройки

Обычный запуск:

```text
$book-translator [ПАПКА] [продолжить|начать-заново] [циклы=1..20] [верификация=после-каждого-файла|в-финале]
```

Повторный перевод конкретного файла:

```text
$book-translator [ПАПКА] перевести-заново [ИМЯ-ФАЙЛА] [циклы=1..20] [верификация=...]
```

Примеры:

```text
$book-translator C:\Books\NovelRu продолжить циклы=8
$book-translator C:\Books\NovelRu перевести-заново 002-chapter.rtf
```

Равнозначна естественная просьба: «переведи вторую главу заново с учетом обновленного state». Если имя неоднозначно, плагин покажет совпадения и попросит выбрать файл.

Настройки по умолчанию находятся в `config.ini`:

```ini
[перевод]
режим = продолжить
максимум_циклов = 5
пользовательская_верификация = в_финале
```

Аргументы текущего сообщения важнее `config.ini`. Значение `максимум_циклов` задает число независимых запусков верификатора. Между ними редактор исправляет конкретные замечания; при чистом отчете цикл завершается раньше.

Режимы пользовательской приемки:

- `в_финале` — все новые файлы переводятся и публикуются, после чего плагин просит одобрить результат целиком;
- `после-каждого-файла` — обработка следующего файла начинается только после одобрения текущего.

Команда `начать-заново` сначала показывает, какие результаты и служебные данные будут заменены, и продолжает только после подтверждения. Исходники и пользовательские настройки не удаляются.

## Как устроен перевод

Для каждого файла плагин выполняет короткую контролируемую последовательность:

```text
проверка исходника и очереди
        ↓
анализ сцены и предварительное дополнение state
        ↓
художественный перевод
        ↓
независимая верификация и точечные правки
        ↓
обновление памяти книги и саммари
        ↓
сборка и проверка RTF
        ↓
публикация и пользовательская приемка
```

Переводчик сначала анализирует весь файл: определяет точку зрения частей, голос рассказчика и персонажей, эмоциональный подтекст, значимые повторы, паузы, ритм и контекстные значения терминов. Только после этого он переводит текст в том же контексте.

Верификатор независимо сопоставляет оригинал и перевод. Редактор исправляет только конкретные замечания, не переписывая главу произвольно. Хранитель state затем финализирует глоссарий, персонажей, сюжет, стиль, решения и краткое саммари текущего файла.

Если после последнего автоматического раунда остаются смысловые или редакторские вопросы, перевод не теряется: замечания прикрепляются к соответствующим фрагментам как RTF-аннотации. Публикацию блокируют только поврежденная структура или документ, который нельзя безопасно собрать.

## Проверка пользователем

Откройте опубликованный файл из ссылки в чате. Замечание можно передать двумя способами:

1. Добавить штатную аннотацию непосредственно в RTF.
2. Выделить фрагмент в ChatGPT App, выбрать `Add to chat` и описать требуемую правку.

Если вы возвращаете файл с замечаниями, плагин запускает новый экземпляр редактора только для этих правок, проверяет результат и атомарно обновляет тот же опубликованный RTF, а затем снова показывает прежнюю ссылку для приемки. Цикл «замечания → редактор → обновленный файл → приемка» повторяется без ограничения, пока вы явно не одобрите результат без новых замечаний. Настройка `максимум_циклов` относится только к автоматической проверке и этот цикл не ограничивает.

Версионированный файл создается только по явной команде `перевести-заново`, когда выбранный исходник полностью переводится с актуальными настройками и state. Обычные автоматические проверки, редакторские правки и пользовательская приемка новых имен версий не создают.

Исправленные аннотации остаются видимыми до явного одобрения, чтобы можно было проверить выполненные изменения. После одобрения без замечаний аннотации удаляются из принятой версии.

Во время приемки не редактируйте основной текст опубликованного RTF вручную. Если требуется собственная редакция текста, сначала сообщите об этом в чате: плагин отличает новые аннотации от прямого изменения документа и предложит безопасный вариант продолжения.

## Новые главы и повторный перевод

При каждом продолжении заново сканируется `input/`:

- новые файлы добавляются в очередь независимо от их позиции;
- уже опубликованные и не изменившиеся файлы считаются готовыми;
- добавление главы после завершения книги снова открывает проект;
- изменение готового оригинала требует явной команды повторного перевода.

Повторный перевод использует актуальные пользовательские сведения. Он заменяет только автоматический вклад выбранного файла в рабочей копии state и не пересчитывает последующие главы. Новый вариант публикуется рядом с прежним как отдельная датированная ревизия, например `002-chapter.ru.v002.20260822.rtf`.

Перед заменой создается резервная копия прежнего результата, progress и state. При ошибке плагин восстанавливает предыдущее согласованное состояние.

## Что хранится в state

| Файл | Назначение |
|---|---|
| `glossary.md` | имена, названия и обязательные варианты терминов |
| `decisions.md` | переводческие решения и нерешенные вопросы |
| `characters.md` | персонажи, отношения, обращения и особенности речи |
| `style-guide.md` | голос рассказчика, регистр, ритм, повторы, паузы и оформление |
| `story-state.md` | события сюжета, факты мира, хронология и эмоциональный контекст |
| `chapter-summaries.md` | краткие итоги переведенных файлов |

Каждый файл разделен на пользовательскую область и автоматические подразделы отдельных исходников. Пользовательскую область можно дополнять в любое время; плагин сохраняет ее без автоматической нормализации.

## Литературные правила

Перевод должен звучать как самостоятельная русская художественная проза, а не как копия английского синтаксиса. Плагин сохраняет факты, неоднозначность, черный юмор, индивидуальные голоса, значимые повторы, ритм, метафоры и авторскую степень прямоты. Он не добавляет пояснений и не смягчает тяжелые или взрослые сцены.

Имена и термины передаются последовательно; пользовательский глоссарий имеет абсолютный приоритет. Прямая речь оформляется по нормам русской прозы. В переводе всегда используется `е` вместо `ё`; пользовательский state при этом не изменяется автоматически.

Полные критерии находятся в `skills/book-translator/references/`.

## Надежность и ограничения

- Исходные RTF открываются только для чтения.
- Результат, progress и state фиксируются согласованно; неуспешная публикация откатывается.
- Неудачная транзакция сохраняется для диагностики и не мешает повторить публикацию.
- Групповое одобрение нескольких файлов либо применяется целиком, либо полностью откатывается.
- Символические ссылки и Windows reparse points внутри `input/` отклоняются.
- Поддерживаются абзацы, заголовки, курсив, полужирное начертание, сноски, разрывы сцен и сохранение изображений.
- Небезопасная либо непонятная RTF-конструкция отклоняется до перевода, чтобы не потерять текст молча.
- Проект прежней схемы не мигрируется автоматически.
- Не запускайте одновременно два перевода одного рабочего каталога.
- Версия 0.2.0 предназначена только для направления английский → русский и только для RTF.

## Рекомендуемая модель координатора

Для основного чата, управляющего файлами и ролевыми агентами, рекомендуется:

```toml
model = "gpt-5.6-terra"
model_reasoning_effort = "medium"
```

Навык не может переключить модель текущего чата самостоятельно. Модели переводчика, верификатора, редактора и хранителя state закреплены в их проектных TOML и не наследуются от координатора.

## Частые проблемы

### Навыки не появились после установки

Перезапустите приложение, проверьте marketplace командой `codex plugin marketplace list` и убедитесь, что плагин установлен и включен. После обновления marketplace может потребоваться обновить или переустановить плагин.

### Инициализатор сообщает о конфликте агента

В проекте уже есть измененный TOML с таким именем. Инициализатор сохраняет пользовательский файл. Заменяйте его только после просмотра и отдельного подтверждения точного имени.

### Готовый оригинал изменился

Не удаляйте progress и манифест. Явно попросите перевести этот файл заново либо восстановите прежнюю версию оригинала.

### Плагин не принимает измененный результат

Во время пользовательской приемки добавляйте аннотации или используйте `Add to chat`. Прямое изменение основного текста требует отдельного согласования.
