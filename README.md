# Переводчик художественных книг для Codex

`book-translator-plugin` — локальный русскоязычный плагин для последовательного художественного перевода книг с английского на русский. Он обрабатывает главы строго по порядку, использует отдельные ролевые custom agents с чистым контекстом, проверяет полноту перевода и публикует главу только после приёмки.

Плагин рассчитан на романы, разделённые на отдельные файлы глав. Пользователь запускает workflow из чата, выбирает папку книги, выходной формат и режим продолжения.

> Текущая версия: `0.1.0`. Плагин пока устанавливается локально и не опубликован в общем каталоге плагинов.

## Главное

- Переводит английскую художественную прозу на естественный русский язык без буквальной англоязычной кальки.
- Обрабатывает главы только последовательно: следующая глава не начинается до окончательной фиксации предыдущей.
- Не пропускает блоки текста: структура и полнота проверяются механически до публикации.
- Разделяет перевод, независимую проверку, редактуру и обновление памяти между четырьмя custom agents.
- Запускает каждый ролевой этап в новом чистом контексте.
- Поддерживает продолжение после прерывания без повторного перевода принятой главы.
- Хранит глоссарий, сведения о персонажах, стиль, сюжетное состояние, решения и краткие итоги глав.
- На Windows и macOS работает с DOCX; на macOS дополнительно поддерживает Pages через установленное приложение Pages.
- Не изменяет, не перемещает и не удаляет исходные главы.

## Как работает перевод

Для каждой главы выполняется один и тот же контролируемый цикл:

```text
предварительная проверка
        ↓
извлечение блоков и фиксация структуры
        ↓
художественный перевод
        ↓
механическая проверка полноты
        ↓
независимая смысловая проверка
        ↓
точечная литературная редактура
        ↓
повторная проверка
        ↓
сборка DOCX или Pages
        ↓
обновление памяти проекта
        ↓
транзакционная публикация главы
        ↓
следующая глава
```

Если после первой редактуры остаются подтверждённые ошибки, разрешён ещё один цикл `редактор → проверяющий`. Третья редактура запрещена: при оставшейся критической проблеме глава не публикуется, а workflow останавливается с отчётом.

Длинная глава может делиться на части только между блоками. Все части переводит один экземпляр переводчика последовательно, поэтому голос, сцена и незавершённые смысловые связи не теряются на границах частей.

## Состав плагина

| Путь | Назначение |
|---|---|
| `.codex-plugin/plugin.json` | Манифест плагина |
| `skills/book-translator/SKILL.md` | Главный координатор workflow и команда `$book-translator` |
| `agents/translator.toml` | Художественный переводчик |
| `agents/verifier.toml` | Независимый проверяющий полноты, смысла и естественности |
| `agents/editor.toml` | Литературный редактор подтверждённых замечаний |
| `agents/state-updater.toml` | Хранитель памяти проекта |
| `skills/book-translator/references/` | Универсальные правила перевода и проверки |
| `skills/book-translator/assets/` | Русскоязычные шаблоны памяти и конфигурации |
| `skills/book-translator/scripts/documents.py` | Проверка, извлечение и сборка документов |
| `skills/book-translator/scripts/progress.py` | Этапы, контрольные точки, транзакции и восстановление |
| `skills/book-translator/scripts/install-agents.py` | Безопасная установка четырёх custom agents |
| `skills/book-translator/scripts/pages-bridge.applescript` | Разрешённый пользователем обмен с Pages на macOS |
| `hooks/check-progress.py` | Проверка активного workflow перед остановкой Codex |
| `tests/` | Автоматические и ручные приёмочные проверки |

Плагин не содержит MCP-сервера, отдельного приложения или графического интерфейса. Для локального перевода они не нужны.

### Почему custom agents устанавливаются отдельно

Custom agents входят в поставку плагина и хранятся в каталоге `agents/`, но текущая официальная схема `.codex-plugin/plugin.json` не содержит поля `agents`. Манифест может подключать skills, MCP-серверы, apps и hooks; произвольное поле `agents` не зарегистрирует роли в Codex.

Сам Codex загружает пользовательские роли из `~/.codex/agents/` либо проектные роли из `.codex/agents/`. Поэтому `install-agents.py` отдельно и с подтверждением копирует четыре TOML-файла в поддерживаемый каталог. Это временная граница платформы, а не отделение агентов от продукта: если OpenAI добавит официальный manifest-контракт для agents, установку можно будет перенести в `plugin.json`.

Подробное официальное описание поддерживаемых частей и полей манифеста приведено в [документации OpenAI о структуре плагина](https://developers.openai.com/plugins/build/plugins). Правила регистрации отдельных ролей приведены в [документации OpenAI о настройке пользовательских агентов](https://learn.chatgpt.com/docs/agent-configuration/subagents).

## Поддерживаемые форматы

| Система | Вход | Выход | Условия |
|---|---|---|---|
| `Windows` | `.docx` | `.docx` | `Python 3.10+` и `python-docx` |
| `macOS` | `.docx` | `.docx` | `Python 3.10+` и `python-docx` |
| `macOS` | `.pages` или `.docx` | `.pages` | Установленный Pages и явное разрешение на запуск |
| `macOS` | `.pages` | `.docx` | Установленный Pages и явное разрешение на экспорт |

Режим `как-в-оригинале` сохраняет формат каждой исходной главы. Pages на Windows не поддерживается: используйте DOCX либо перенесите проект на Mac с Pages.

## Что сохраняется в DOCX

Поддерживаются:

- обычные абзацы и заголовки;
- разрывы сцен;
- курсив и полужирное начертание;
- сноски;
- порядок и границы текстовых блоков.

Первая версия заранее отклоняет документы с таблицами, гиперссылками, комментариями, отслеживаемыми изменениями, связанными текстовыми блоками и другими неподдерживаемыми конструкциями. Это предотвращает тихую потерю текста.

## Требования

- приложение `ChatGPT desktop app` с локальным Codex и поддержкой плагинов;
- Python 3.10 или новее;
- `python-docx>=1.2,<2`;
- четыре custom agents из каталога `agents/`;
- для Pages — macOS и установленное приложение Pages;
- доступ на чтение к исходникам и на запись в папку проекта.

Схема запуска субагентов должна поддерживать выбор роли через `agent_type` и отключение наследования контекста. Если доступный runtime не предоставляет `agent_type`, skill безопасно остановится и не заменит custom agent универсальным агентом.

## Установка плагина

Актуальная схема OpenAI для локальной разработки использует персональный или репозиторный marketplace. Подробный порядок создания каталога, добавления локальной записи и установки описан в [официальном руководстве OpenAI по упаковке плагинов](https://developers.openai.com/plugins/build/plugins).

Ниже приведена персональная установка, доступная во всех ваших проектах.

### 1. Разместите каталог плагина

Скопируйте или клонируйте репозиторий в:

- Windows: `%USERPROFILE%\.codex\plugins\book-translator-plugin`
- Для компьютеров Mac: `~/.codex/plugins/book-translator-plugin`

Можно использовать другое место внутри корня персонального marketplace, но тогда измените `source.path` в следующем шаге.

Пример клонирования в рекомендуемый каталог Windows:

```powershell
git clone "https://github.com/vspanov/book-translator-plugin.git" "$env:USERPROFILE\.codex\plugins\book-translator-plugin"
```

Пример клонирования на компьютере Mac:

```sh
git clone "https://github.com/vspanov/book-translator-plugin.git" "$HOME/.codex/plugins/book-translator-plugin"
```

### 2. Добавьте персональный marketplace

Создайте или обновите файл:

- Windows: `%USERPROFILE%\.agents\plugins\marketplace.json`
- Для компьютеров Mac: `~/.agents/plugins/marketplace.json`

Минимальный пример:

```json
{
  "name": "local-books",
  "interface": {
    "displayName": "Локальные плагины для книг"
  },
  "plugins": [
    {
      "name": "book-translator-plugin",
      "source": {
        "source": "local",
        "path": "./.codex/plugins/book-translator-plugin"
      },
      "policy": {
        "installation": "AVAILABLE",
        "authentication": "ON_INSTALL"
      },
      "category": "Productivity"
    }
  ]
}
```

Если `marketplace.json` уже существует, добавьте объект плагина в имеющийся массив `plugins` — не заменяйте остальные записи.

### 3. Установите плагин в приложении

1. Перезапустите приложение `ChatGPT desktop app`.
2. Откройте каталог плагинов.
3. Выберите источник «Локальные плагины для книг».
4. Найдите `book-translator-plugin` и установите его.
5. Проверьте, что skill `book-translator` доступен в новом чате.
6. Просмотрите `hooks/hooks.json` и явно доверьте hook только после проверки его команды.

Установка или включение плагина не означает автоматического доверия его hook: Codex отдельно просит просмотреть и разрешить неменеджерский hook.

### Обновление локальной версии

Обновите файлы в каталоге, на который указывает marketplace, затем перезапустите ChatGPT desktop app. Локальная установленная копия загружается из кеша плагинов, поэтому при необходимости обновите или переустановите запись через каталог плагинов.

## Установка Python-зависимости

Плагин сам проверяет Python и `python-docx`. Если зависимость отсутствует, он показывает точную команду и ждёт разрешения; скрытая установка запрещена.

При желании установите зависимость заранее.

### Windows

```powershell
py -3 -m pip install "python-docx>=1.2,<2"
```

### Установка зависимости на компьютере Mac

```sh
python3 -m pip install "python-docx>=1.2,<2"
```

Если у вас несколько Python-окружений, используйте тот интерпретатор, которым Codex будет запускать плагин.

## Однократная установка custom agents

Плагину нужны четыре отдельные роли:

- `book_translator_translator` — создаёт полный художественный перевод;
- `book_translator_verifier` — независимо сопоставляет оригинал и перевод;
- `book_translator_editor` — исправляет только подтверждённые замечания;
- `book_translator_state_updater` — готовит следующую полную версию памяти.

Установщик сначала умеет показать план без записи. Подставьте абсолютные пути к Python, плагину и каталогу `agents` Codex.

### Команды для Windows (PowerShell)

```powershell
& "<путь-к-python>" "<абсолютный-путь-к-плагину>\skills\book-translator\scripts\install-agents.py" --source "<абсолютный-путь-к-плагину>\agents" --target "<абсолютный-каталог-agents-Codex>" --plan
& "<путь-к-python>" "<абсолютный-путь-к-плагину>\skills\book-translator\scripts\install-agents.py" --source "<абсолютный-путь-к-плагину>\agents" --target "<абсолютный-каталог-agents-Codex>" --confirm
```

Оператор `&` обязателен: без него PowerShell не запускает заключённый в кавычки путь к программе.

Типичный каталог назначения:

```text
%USERPROFILE%\.codex\agents
```

### Команды для POSIX-систем

```sh
"<путь-к-python>" "<абсолютный-путь-к-плагину>/skills/book-translator/scripts/install-agents.py" --source "<абсолютный-путь-к-плагину>/agents" --target "<абсолютный-каталог-agents-Codex>" --plan
"<путь-к-python>" "<абсолютный-путь-к-плагину>/skills/book-translator/scripts/install-agents.py" --source "<абсолютный-путь-к-плагину>/agents" --target "<абсолютный-каталог-agents-Codex>" --confirm
```

Типичный каталог назначения:

```text
~/.codex/agents
```

Если план сообщает `отличается`, не разрешайте массовую перезапись. После проверки конкретного файла повторите команду с подтверждением:

```text
--confirm --overwrite "<точное-имя.toml>"
```

После установки перезапустите приложение и проверьте доступность всех четырёх ролей.

## Подготовка книги

Рекомендуемая структура до первого запуска:

```text
my-book/
└── input/
    ├── 001-пролог.docx
    ├── 002-глава-1.docx
    ├── 003-глава-2.docx
    └── 004-эпилог.docx
```

Главы можно положить в `input/` или непосредственно в корень проекта, но не в оба места одновременно. Имена определяют естественный порядок: `chapter-2.docx` идёт перед `chapter-10.docx`.

После инициализации появятся:

```text
my-book/
├── input/                 # исходные главы
├── output/                # опубликованный русский перевод
├── state/                 # память проекта
│   ├── characters.md
│   ├── glossary.md
│   ├── style-guide.md
│   ├── story-state.md
│   ├── chapter-summaries.md
│   └── decisions.md
├── work/                  # блоки, отчёты и контрольные точки
└── progress.json          # текущее состояние workflow
```

Пользователь может читать и вручную дополнять файлы `state/*.md`. Все они русскоязычные. Ручной глоссарий имеет абсолютный приоритет перед автоматически выбранными вариантами.

## Запуск из чата

Каноническая форма:

```text
$book-translator [ПАПКА] [формат: pages|docx|как-в-оригинале] [продолжить|начать-заново]
```

| Аргумент | Значение по умолчанию | Допустимые значения |
|---|---|---|
| `ПАПКА` | текущая папка | относительный или абсолютный путь к проекту |
| `формат` | `как-в-оригинале` | `docx`, `pages`, `как-в-оригинале` |
| `режим` | `продолжить` | `продолжить`, `начать-заново` |

Параметры текущего сообщения важнее `skills/book-translator/assets/config.ini`. Естественная русская просьба о переводе книги равнозначна явному вызову skill.

### Первый перевод в текущей папке

```text
$book-translator Переведи книгу в текущей папке.
```

### Явный путь и результат DOCX

```text
$book-translator "C:\Books\Novel" формат: docx продолжить
```

### Формат Pages на компьютере Mac

```text
$book-translator "/Users/me/Books/Novel" формат: pages продолжить
```

Codex сначала покажет операции с Pages и запросит разрешение. Без подтверждения приложение Pages не запускается.

### Сохранить формат оригинала

```text
$book-translator "/Users/me/Books/Novel" как-в-оригинале продолжить
```

### Продолжить после прерывания

```text
$book-translator Продолжи перевод книги в текущей папке с последней контрольной точки.
```

### Начать заново

```text
$book-translator "C:\Books\Novel" формат: docx начать-заново
```

Перед очисткой плагин покажет затрагиваемые `output/`, `state/`, `progress.json` и рабочие контрольные точки. Перезапуск выполняется только после явного подтверждения и проверенной резервной копии. Исходники не затрагиваются.

### Изменить формат результата

```text
$book-translator Переведи главы из текущей папки в DOCX и продолжи существующий проект.
```

Если выбранный формат конфликтует с уже опубликованными файлами или текущим состоянием проекта, плагин остановится и объяснит безопасные варианты.

## Продолжение и восстановление

При повторном вызове в режиме `продолжить` плагин:

1. проверяет манифест, состояние и контрольные суммы;
2. завершает подготовленную, но не полностью опубликованную транзакцию;
3. не переводит повторно уже принятую главу;
4. продолжает со следующего незавершённого этапа;
5. оставляет исходники и последнюю принятую память неизменными при ошибке.

Не удаляйте `work/`, `state/` или `progress.json` между запусками: они нужны для безопасного продолжения.

## Память проекта

| Файл | Что хранит |
|---|---|
| `characters.md` | персонажи, обращения, отношения и особенности голосов |
| `glossary.md` | имена, названия, термины мира и обязательные варианты перевода |
| `style-guide.md` | выбранные стилистические и издательские правила |
| `story-state.md` | актуальные события, тайны и состояние сюжетных линий |
| `chapter-summaries.md` | краткие итоги уже принятых глав |
| `decisions.md` | переводческие решения и нерешённые вопросы |

Память обновляется только один раз после окончательной приёмки главы. Черновик, отдельная часть главы или неуспешная редактура не могут изменить действующее состояние.

## Практические рекомендации

1. Используйте отдельную папку для каждой книги.
2. Нумеруйте главы с ведущими нулями: `001`, `002`, `003`. Так порядок очевиден человеку и программе.
3. Не смешивайте источники в корне и `input/`.
4. До первого запуска заполните `glossary.md`, если у вас уже есть утверждённые имена и термины.
5. Добавьте в `style-guide.md` желаемые обращения, вариант `ё/е`, правила прямой речи и допустимую степень разговорности.
6. Для работы попеременно на Windows и Mac выбирайте DOCX как переносимый формат.
7. Перед импортом удалите из исходника неподдерживаемые таблицы, комментарии и отслеживаемые изменения либо сохраните упрощённую копию главы.
8. Не редактируйте уже обработанный исходный файл молча. Плагин заметит изменение и предложит сохранить прежний результат либо заново обработать изменённую и последующие главы.
9. Просматривайте готовые главы в `output/`, но не меняйте служебные файлы транзакций вручную.
10. Храните отдельную резервную копию оригинала, даже несмотря на то что плагин работает с исходниками только на чтение.
11. Для длинного романа периодически проверяйте `characters.md`, `glossary.md` и `decisions.md`: ручные уточнения помогают удерживать авторский замысел.
12. Не запускайте несколько переводов одного проекта одновременно.

## Безопасность и целостность

- В `work/manifest.json` записываются порядок и SHA-256 исходных глав.
- Изменение обработанного исходника блокирует автоматическое продолжение.
- Результат, память и контрольная точка публикуются одной восстанавливаемой транзакцией.
- Служебные пути проверяются на выход из проекта и небезопасные файловые ссылки.
- Stop-hook не даёт незаметно завершить активный workflow на промежуточном этапе.
- Объяснённая ошибка может корректно завершить работу без ложного сообщения об успехе.

Эти меры защищают от случайной порчи и несогласованного локального изменения. Они не являются криптографической защитой от владельца системы, намеренно переписавшего все файлы и контрольные суммы.

## Частые проблемы

### Skill не появился после установки

- перезапустите приложение `ChatGPT desktop app`;
- проверьте запись в `marketplace.json`;
- убедитесь, что `source.path` начинается с `./` и указывает внутрь корня marketplace;
- откройте каталог плагинов и проверьте, что плагин установлен и включён;
- после изменения локальных файлов обновите или переустановите локальную запись.

### Не найдены custom agents

Запустите `install-agents.py` сначала с `--plan`, затем после проверки — с `--confirm`. Перезапустите приложение.

### Отсутствует `python-docx`

Установите `python-docx>=1.2,<2` именно в используемый Codex интерпретатор Python. Путь к интерпретатору выводится на предварительной проверке.

### Runtime не поддерживает `agent_type`

Это несовместимость текущей схемы запуска субагентов. Плагин специально останавливается, потому что передача имени роли через обычное имя задачи не гарантирует запуск нужного custom agent. Обновите Codex до версии с поддержкой выбора custom agent и повторите запуск.

### Pages запрошен на Windows

Выберите выход `docx` либо перенесите проект на Mac с установленным Pages.

### DOCX отклонён до перевода

Откройте сообщение предварительной проверки. Обычно причина — неподдерживаемая таблица, гиперссылка, комментарий, отслеживаемое изменение, повреждённый OOXML или конфликт выходного имени. Исправьте копию исходного документа и снова запустите проект.

### Исходная глава изменилась

Не удаляйте манифест вручную. Выберите один из предложенных вариантов: сохранить прежний опубликованный результат либо заново перевести изменённую главу и все следующие.

### Stop-hook не разрешает завершить задачу

В проекте осталась активная глава или несогласованное состояние. Попросите продолжить перевод либо исправить указанную ошибку. Не удаляйте `work/active.json` вручную.

## Ограничения версии 0.1.0

- Только английский → русский.
- Только отдельные файлы глав `.docx` и `.pages`.
- Нет CAT-интеграции, Translation Memory, API, MCP-сервера и отдельного интерфейса.
- Нет параллельной обработки глав и частей главы — это намеренное ограничение качества и целостности.
- Не поддерживаются таблицы, гиперссылки, комментарии, отслеживаемые изменения и связанные текстовые блоки.
- Полный workflow требует host со схемой spawn, содержащей `agent_type`.
- Реальная приёмка чистого контекста custom agents ещё должна быть выполнена в совместимом runtime.
- Реальная Pages→Pages приёмка на macOS ещё не выполнена в текущей Windows-среде.

Фактические протоколы приёмки находятся в `tests/acceptance/`.

## Проверки для разработчиков

Используйте тот Python, которым будет запускаться плагин.

### Проверки в Windows PowerShell

```powershell
& "<путь-к-python>" -m unittest discover -s tests -p "test_*.py" -v
& "<путь-к-python>" -m json.tool .codex-plugin/plugin.json
& "<путь-к-python>" -m json.tool hooks/hooks.json
```

### Проверки в POSIX

```sh
"<путь-к-python>" -m unittest discover -s tests -p "test_*.py" -v
"<путь-к-python>" -m json.tool .codex-plugin/plugin.json
"<путь-к-python>" -m json.tool hooks/hooks.json
```

Ручные приёмочные сценарии:

- `tests/acceptance/clean-context.md` — подтверждение чистого контекста ролевых агентов;
- `tests/acceptance/windows-docx.md` — полный DOCX→DOCX прогон на Windows;
- `tests/acceptance/macos-pages.md` — Pages→Pages прогон на macOS.
